# 專案方向

狀態：使用者方向已確認；設計規則仍待提煉與視覺驗證。

更新日期：2026-11-11（Asia/Hong_Kong）。

## 目標

將《Zenless Zone Zero／絕區零》的視覺語言蒸餾成可重用的 skill，配合可執行預覽與樣張，供日後開發不同工具時套用。交付形式參考 [endfield-ui-skill](https://github.com/hhikr/endfield-ui-skill)，但 ZZZ 的設計規則須由自身參照推導。

## 設計提煉方式

1. 先辨認跨區塊、跨頁面重複出現的特徵，記錄來源與畫面位置。
2. 將介面底色、文字、重點色與角色／宣傳圖片的顏色分開分析。
3. 區分長期視覺語言與單一版本活動的表現，避免把當期宣傳配色直接定為全域規則。
4. 將觀察轉化為有使用情境的規則：何時使用、如何組合、何時收斂。
5. 用不含角色圖與官方標誌的預覽驗證辨識度，再決定哪些規則適合固定、哪些應可調。

每項規則保留三種狀態：**已觀察**、**候選設計決定**、**待驗證**。候選決定不能冒充官方規範；官網證據也不能直接代表遊戲內介面。

## 第一版建議交付

以下是工作建議，不是已實作內容，也不是使用者已指定的完整檔案清單。

| 交付 | 內容 |
| --- | --- |
| `SKILL.md` | 觸發用途、風格核心、套用步驟、按需參照路徑、交付自查 |
| `references/` | 視覺來源與分析、tokens、字體、形狀、組合方式、動效與響應式規則 |
| `assets/` | 平台中立 tokens、Web 樣式、自製的必要圖形；僅加入實際有用的資源 |
| `preview/` | 風格與元件總覽、桌面／手機示例、動效重播、正反例 |
| 靜態樣張 | 從實際預覽產生，讓不啟動專案的人也能檢視效果 |

先以 Web 為範圍；原生 App、Flutter、React Native 不列入目前第一版。框架、套件管理器、正式 skill 名稱與預覽工具題材尚未選定。

## 預覽應回答的問題

- 移除角色圖、官方標誌和遊戲名稱後，是否仍有明確的 ZZZ 靈感？
- 辨識度是否由字體、形狀、色彩比例與構圖共同建立？
- 同一套規則能否應用於不同工具內容，而不必照搬同一張版型？
- 英文為主、中文為輔時，標題與正文是否自然？雙語不代表每一行都強制重複翻譯。
- 桌面與手機是否均可閱讀和操作，而非將桌面海報直接縮小？
- 強烈裝飾是否集中於合適位置，沒有遮擋表單、長文字與實際操作？

## 驗證方向

視覺驗證以來源對照與實際渲染為主，檢查字體載入、長文字、手機重排和互動狀態。鍵盤焦點、觸控操作、文字對比與減少動效支援屬於工具產品的實作要求，不能假稱是從官網觀察到的規則。

精確色碼、字體選型、尺寸比例、動效曲線與時長應在證據或原型驗證後確立，目前不凍結成 tokens。
