## 換裝置後的接續順序

1. 同步整個專案資料夾，從根目錄 `README.md` 開始閱讀。
2. 保留已確認的四個方向，不重新從需求訪談開始。
3. 若額外材料已可取得，先整理最能表現使用者偏好的畫面，補充來源與簡短註解。
4. 對照官網筆記，確認重複元素；將新觀察與原有假設相互校正。
5. 接續實作時，先確立少量核心規則與候選 tokens，做不依賴角色圖／官方標誌的風格樣張。
6. 驗證桌面和手機的辨識度與可讀性，再整理成正式 skill、可用樣式和預覽。

若暫時仍沒有額外材料，可以繼續官網分析或製作標示為候選的原型；不要將材料缺席視為整個專案無法推進。這份交接文件記錄後續路徑，不代表本輪已要求完成實作。

## 日後補充材料

優先補「能決定風格的材料」，毋須湊齊指定操作介面或固定張數。

| 優先級 | 材料 | 最有用的註解 |
| --- | --- | --- |
| 高 | 最喜歡、最能代表 ZZZ 味道的幾個畫面 | 喜歡的是字形、色彩、形狀、構圖、紋理還是互動？ |
| 高 | 不同場景中反覆出現的元素 | 哪些元素看起來是共通語言，而非某個角色／活動限定？ |
| 中 | 短互動錄影或影片連結附時間戳 | 指出想保留的轉場或回饋節奏。 |
| 可選 | 不喜歡的方向或反例 | 哪些效果過於吵雜、難讀或不像你要的 ZZZ 風格？ |
| 可選 | 常做的工具例子 | 可用來選預覽題材；不將單一工具鎖死為 skill 的用途。 |

截圖以原尺寸、完整畫面為佳，局部細節可另附裁切。可暫用 `incoming/` 放新材料，並附簡短說明；本輪尚未建立該目錄。無須先提供色碼、字體名稱或動畫參數。
